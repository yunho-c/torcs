VS 2022 update notes, first step (32 bit, still self containing and static builds, no dependency to runtime distributable):
----------------------------------------------------------------------------------------------------------------------------
zlib-1_3_1 notes (zlib 1.3.1):
- For static library I needed to undefine ZLIB_WINAPI, otherwise the symbol conventaion mismatches
  (missing symbols on linking). Can be checked with "dumpbin /LINKERMEMBER zlib1_vs2022_32.lib | findstr gz",
  replace gz with your missing symbol
- Built with contrib project file in zlib-1_3_1\contrib\vstudio\vc17

libpng notes (libpng 1.6.50):
- Build with project file in lpng1650\projects\vstudio
- Adopt path in zlib.props for the zlib headers
- Do NOT use the zlib built by libpng, it does only define symbols used by libpng
- Release build had debugging info, switched that off to avoid missing pdb warnings in the TORCS build
- patched ul.h, because it did not check if WIN32_LEAN_AND_MEAN was already set
#ifndef WIN32_LEAN_AND_MEAN
#  define WIN32_LEAN_AND_MEAN
#endif

freeglut-3.6.0:
- build with 
- cmake -B build32 -G "Visual Studio 17 2022" -A Win32 -DCMAKE_INSTALL_PREFIX=install32 -DCMAKE_C_FLAGS_RELEASE="/MT" -DCMAKE_CXX_FLAGS_RELEASE="/MT" -DCMAKE_C_FLAGS_DEBUG="/MTd" -DCMAKE_CXX_FLAGS_DEBUG="/MTd" -DFREEGLUT_BUILD_DEMOS=OFF -DFREEGLUT_BUILD_TESTS=OFF
- cmake --build build32 --config Release
- cmake --install build32 --config Release
- Check if "/MT" option was taken: dumpbin /dependents install32\bin\freeglut.dll
- Should NOT contain CRUNTIME140.dll, api-ms-win-crt-heap-l1-1-0.dll, etc.
